一眼看懂：当前实现的数据流

1. 环境状态车辆、路线、冲突区、已调度状态、zone 可用时间。
2. 可行集合compute_feasible_set 返回每个 operation 是否可调度。
3. 异构图build_hetero_graph 构造 node features 和 edge_index。
4. HGT 编码每类节点先投影到 hidden_dim，再经过多层 HGTConv。
5. Actor每个 operation 得到一个 logit；不可行动作被设为 -inf。
6. Critic + PPO未调度 operation 均值池化，输出状态价值，供 GAE/PPO 更新。

Node 输入结构

operation 节点 [num_ops, 6]

一个 operation 表示“某辆车在路线中的某个位置通过某个 conflict zone”。它也是 actor 可以选择的动作单位。

d(i,j): 是否已调度 c(i,j): earliest finish p(i,j): processing time j / n_i: route progress is_schedulable n_conflicts

vehicle 节点 [num_veh, 4]

vehicle 节点提供车辆级上下文，例如到达时间、路线长度和速度。它通过 owns 边给 operation 传递所属车辆信息。

r_i: arrival time n_i: route length velocity zones_done

zone 节点 [num_zones, 5]

zone 节点描述共享资源状态。它通过 hosts 边告诉 operation 当前 conflict zone 的占用和竞争情况。

occupied time_free n_competing x y

Edge / Relation 结构

关系 方向 语义 edge_attr
seq operation -> operation 同一辆车的路线先后顺序：前一个 zone operation 必须早于后一个。 [processing_time / max_p]
lane operation -> operation 同一入口车道的先到先行关系，leader 的首个 operation 指向 follower 的首个 operation。 [arrival_gap / max_r]
conflict operation <-> operation 不同车辆竞争同一个 zone 的 active conflict，当前实现按双向边加入。 [arrival_delta, urgency_src, urgency_dst]
owns vehicle -> operation 车辆拥有自己的所有 route operations。 无
hosts zone -> operation 某个 conflict zone 承载所有需要使用它的 operations。 无

代码准确性提示：graph_builder.py 会构造部分 edge_attr， 但当前 IntersectionHGT.forward() 调用的是 conv(h, edge_index_dict)，没有把 edge_attr 传入 HGTConv。 因此论文中不要写成“当前模型已经使用边属性注意力偏置”。

HGT Encoder 是怎么实现的

IntersectionHGT 固定声明三类节点和五类关系，并把这个 metadata 交给 PyG 的 HGTConv。每种节点先经过 lazy Linear(-1, hidden_dim) 投影到同一个隐藏维度，所以 operation 的 6 维、vehicle 的 4 维、zone 的 5 维可以进入同一个 HGT 层。

每一层 HGTConv 后，代码对返回的目标节点做 ReLU + residual + LayerNorm。 因为当前所有边的目标节点都是 operation，HGTConv 主要更新 operation embedding。 vehicle 和 zone 是源节点上下文，会被原样保留到下一层，继续作为消息源。 

h = {
  ntype: relu(input_proj[ntype](x))
  for ntype, x in x_dict.items()
}

for conv, norm in layers:
  h_new = conv(h, edge_index_dict)
  h_next = dict(h)
  for ntype, emb in h_new.items():
    h_next[ntype] = norm[ntype](relu(emb) + h[ntype])
  h = h_next

return h["operation"]

直观理解：operation 节点是“决策对象”，vehicle 和 zone 节点是“上下文来源”。 HGT 的 typed relation 让模型区分 route 顺序、同车道顺序、冲突关系、车辆归属和 zone 承载关系。

Actor-Critic 输出结构

Actor 输出

Actor 对每个 operation embedding 输出一个标量 logit。

logits = MLP_actor(op_emb)

然后使用 feasible_mask 把不可行动作设为 -inf，再构造 categorical policy。

Critic 输出

Critic 不拼接显式 global feature；它从未调度 operation embedding 中做均值池化。

h_G = mean(h_o for o in U_t)
value = MLP_critic(h_G)

如果所有 operation 都已调度，则回退到所有 operation embedding 的均值。

Feasibility 的双重作用

is_schedulable 作为 operation feature 进入图，让模型知道当前可行动作状态。

真正的约束保证来自 actor 后面的 hard mask：它直接阻止不可行动作被采样。

PPT 小模板：一页介绍 HGT 结构

标题

HGT-based Neural Scheduler for JSSP Intersection Control

把当前交通调度状态编码为异构图，用 HGT 学习下一步 operation dispatching preference。

图输入

operation: 调度动作节点 [6] vehicle: 车辆上下文 [4] zone: 共享资源状态 [5] seq / lane / conflict / owns / hosts

模型输出

Actor: 对 operation 节点打分，并用 feasible mask 过滤非法动作。

Critic: 对未调度 operation embeddings 均值池化，估计 PPO value。

可直接放进 PPT 的 3 条 bullet

- Environment state is encoded as a typed graph: operation, vehicle, and zone nodes.
- HGTConv performs relation-aware message passing over seq, lane, conflict, owns, and hosts edges.
- The actor predicts dispatching preference; feasibility is enforced by a hard action mask, while the critic estimates graph-level value from unscheduled operations.

对应代码位置

intersection_scheduler/environment/graph_builder.py 构造 HeteroData，定义所有 node features、edge_index 和 edge_attr。
intersection_scheduler/environment/feasibility.py 计算 feasible action mask，包含已调度、路线前驱、同车道前驱、zone 可用性、车辆到达和 deadlock 检查。
intersection_scheduler/model/hgt.py 定义 HGT metadata、input projection、HGTConv layers、residual LayerNorm，并返回 operation embeddings。
intersection_scheduler/model/policy.py 定义 actor masked policy 和 critic value head。
intersection_scheduler/training/ppo.py 定义 transition、GAE 和 PPO minibatch 更新逻辑。
